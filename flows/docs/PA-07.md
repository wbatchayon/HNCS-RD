## Objectif

Enregistrer les décisions de revue des livrables (jamais les prendre), protéger les champs de revue (P-09) et capitaliser après validation.

## Déclencheur(s)

- `PA-07` : SharePoint : élément de la liste « Livrables » (création ou modification).
  - condition de déclenchement : `@not(equals(toLower(triggerOutputs()?['body/Editor/Email']), toLower(parameters('hncs_ServiceAccountEmail (hncs_ServiceAccountEmail)'))))`
  - statuts cibles (partition [8.2](../../spec.md#82-partition-des-statuts-cibles)) : « À produire », « En cours », « Soumis à revue », « En revue », « Corrections demandées », « Validé », « Archivé / clôturé », « Suspendu / abandonné »

## Entrées

- `PA-07` : Élément `Livrables` créé ou modifié par une personne (toute modification, P-09).

## Traitement pas à pas

1. Champs protégés (P-09) : empreinte courante (format [6.5](../../spec.md#65-formats-des-empreintes-p-09) : `AffectationId`, `Proprietaire`, `Reviseur`, `Echeance`, `DoD` [5 booléens], `NbCorrections`, `DecisionRevue`, `Valideur`, `DateValidation`, `VersionValidee`, `DatePremierDepot`, `DateDepot`, `DateRevue`) comparée clé par clé à `EmpreinteRevue` ; champ modifié par une personne qui n'est ni membre de G_RD ni de G_DRD (pour `Echeance` et `DoD`, le réviseur légitime est aussi habilité), ou `Reviseur` désigné qui n'est ni le référent de l'affectation ni membre de G_DRD → valeurs rétablies, Avertissement, N-92, fin ; empreinte vide → initialisée sans rien rétablir.
2. Création (∅ → À produire) : `IdHNCS` ; `Sujet` copié de l'affectation ; `Reviseur` = compte du référent s'il est vide ou non légitime (N-92 dans ce dernier cas) ; `VersionModele` ; `EcheanceInitiale` ; héritage rompu et propriétaire CSS ; `EmpreinteRevue` initialisée (étape finale).
3. PA-00A (`ItemAuteurEmail` = `Proprietaire`, `ItemValideurEmail` = `Reviseur`) puis contrôles (`G_DOCUMENT`, `G_VALIDEUR_LEGITIME`, `G_COMMENTAIRE_REVUE` comparé à `EmpreinteCommentaire`, `G_CAPITALISATION`) ; refus → annulation, N-90 (création refusée → corbeille).
4. **Soumis à revue** : `DateDepot`, `DatePremierDepot` si vide ; documents liés → « Soumis » ; N-25 au réviseur.
5. **Corrections demandées** : `DateRevue`, `DecisionRevue`, `NbCorrections` + 1, `EmpreinteCommentaire` (une seule fois par décision : `DateRevue` antérieure à la modification) ; action « Correction livrable » (responsable = propriétaire, CSS, échéance = `Echeance` ou aujourd'hui + 5 j si dépassée, idempotente) ; N-26 avec les commentaires.
6. **Validé** : `DateRevue`, `DecisionRevue`, `EmpreinteCommentaire`, `Valideur` = `Editor`, `DateValidation`, `VersionValidee` = version du document ; documents → « Validé » ; actions de correction ouvertes → « Terminée » ; N-27.
7. **Archivé / clôturé** saisi à la main : `G_CAPITALISATION`, `DateArchivage`, documents → « Référence », `JournalFlux` Info.
8. **Suspendu / abandonné** : N-29.
9. PA-00B ; puis tentative de capitalisation d'un livrable « Validé » : `G_CAPITALISATION` → LIV-T08 (FLUX), `DateArchivage`, documents « Référence », `JournalFlux` Info ; sinon N-28 au réviseur (le livrable reste « Validé ») ; enfin mise à jour de `EmpreinteRevue`.

## Contrôles

- `G_CAPITALISATION` : LienDocument renseigné ; si le document est dans LivrablesRD : Sujet et TypeDocument renseignés sur le document ; Definition of Done complète pour POC / plan (règle de validation de liste)
- `G_COMMENTAIRE_REVUE` : CommentaireRevue non vide et différent de EmpreinteCommentaire (valeur lors de la décision précédente)
- `G_DOCUMENT` : LienDocument renseigné, ou au moins un document de LivrablesRD rattaché (Livrable = l'élément)
- `G_VALIDEUR_LEGITIME` : L'acteur (ITEM_VALIDEUR) est le compte du référent de l'affectation (Affectation → Referent → Compte) ou un membre de DIRECTION_RD désigné comme réviseur, et il est différent de ITEM_AUTEUR. Un alternant ne peut jamais valider son propre travail

## Erreurs et reprise

- `PA-07` : PA-00C ; la décision saisie n'est jamais modifiée ; les écritures datées sont protégées contre la double prise en compte d'une resoumission.

## Décision humaine préservée

Validation et demande de corrections réservées au réviseur désigné et légitime (`G_VALIDEUR_LEGITIME`) ; le flux enregistre la décision, ne la prend jamais.

## Points de test

- Alternant désigné réviseur de son propre livrable → validation refusée.
- Corrections avec le même commentaire que la fois précédente → refus `G_COMMENTAIRE_REVUE`.
- Membre G_REF non réviseur qui coche un critère DoD → rétabli, N-92.
- Validation d'un POC avec DoD complète → archivage automatique (LIV-T08), documents « Référence ».
